# v0.2.5.2 音频获取与临时文件验证记录

## 实现范围

本阶段新增独立 `audio.py`，只负责单个 B 站分 P 的 audio-only 下载和临时
文件生命周期；没有接入 `pipeline.py`、`web_service.py` 或
`streamlit_app.py`，也没有修改 README、CLI 默认行为或正式运行依赖。

下载入口使用上下文管理器。yt-dlp 只传入 `format="bestaudio"`、单 URL
和 `noplaylist=True`，不配置音频提取 postprocessor，也不预设 WAV/MP3。
下载出的实际压缩音频后缀保留在临时目录中；正常退出、下载失败和上下文内
可捕获异常都会删除整个专属临时目录，包括残留 `.part` 文件。

`OSError(errno.ENOSPC)` 在临时目录创建、yt-dlp 下载/写入和下载结果枚举
路径统一转换为 `AudioStorageError`；其他 yt-dlp 下载异常转换为
`AudioDownloadError`。

## 自动化验证

使用真实 `tmp_path` 和 fake yt-dlp，仅 mock yt-dlp，不 mock 文件系统，覆盖：

- 成功下载、保留真实后缀和离开上下文后的文件清理。
- yt-dlp 失败、残留 `.part` 清理和 `AudioDownloadError`。
- 上下文调用方抛出异常时的清理。
- 临时目录创建 ENOSPC。
- yt-dlp 直接抛出 ENOSPC，以及 yt-dlp 包装 ENOSPC。
- 只传 audio-only 格式、不配置 postprocessor、不写项目输出目录。

结果：

```text
tests/test_audio.py             7 passed
全量 pytest                     202 passed
```

## 真实 B 站单 P 下载

在开发机使用公开视频 `BV1Li2jBdEzS` 的单 P 链接，通过新增
`audio.download_audio()` 实际下载成功：

- 文件格式：`.m4a`
- 文件大小：3,709,310 bytes（约 3.54 MiB）
- 文件仅存在于系统临时目录下的本次专属临时目录
- 离开上下文后临时目录已删除

## MlxWhisperTranscriber 兼容性

已在具有 `mlx-whisper` 和模型缓存的本机 ASR 环境中，使用上述真实下载
文件直接调用现有 `MlxWhisperTranscriber`。开发机已有可用的 `ffmpeg`，本次
只为 smoke test 临时加入进程 PATH，没有修改项目配置或正式依赖。

真实调用成功：

- 检测语言：`zh`
- 返回带时间戳 Transcript：191 个片段
- 首个片段：`0.0–2.36s，当大家都在谈论人工智能时`

因此，v0.2.5.2 的真实音频格式兼容性、MLX 直接读取和带时间戳输出完成标准
均已通过。该验证没有使用 fake 音频或 fake Transcriber 替代真实结果。
